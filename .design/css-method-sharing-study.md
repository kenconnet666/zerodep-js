# CSS 生成方法共享研究

日期：2026-10-10。研究基线：2322667。现已按下节的真实 IDE 验收结论实施；后文保留研究阶段的候选方案对比。

## 最终实施结论（真实 WebStorm 验收后）

正式采用五组泛型基类的直接继承，不保留每属性的 class/interface 方法补声明。实际 WebStorm 2026.3 EAP 验收发现，补声明会让 clamp/calc 候选只显示名称与返回类型，缺少普通方法的参数列表；直接继承则显示 clamp(minimum: Width, preferred: Width, maximum: Width)，Enter 补全自动插入括号，Ctrl+B 直接定位 generated/base.ts 的实现。raw 的 Ctrl+B 与 rgb 的中文快速文档也已实际验证。

属性参数类型仍由各属性的 Property.* 泛型实参决定，中文方法说明由共享基类提供；因此不再要求每个方法重复显示属性专属示例，也不要求定义落在每属性文件。此前“接口合并保留显示”的建议由本节取代。

正式 new Css() 最小消费构建为 399,512 字节，gzip 32,358 字节，对比基线 501,632 / 34,559 分别减少约 20.4% / 6.4%。文档站客户端实际构建从 555.48 kB / gzip 79.96 kB 降为 474.58 kB / gzip 77.95 kB。

生成器按需导入基类，只重写内容变化的生成文件，避免无意义的 IDE 重索引。类型反例、38 个 CSS 测试、41 个编译器/SSR 相关用例、UI 与文档构建、独立 tgz CSR/SSR 消费和 5 个相关语言探针通过。没有增加 IDE 配置或 SDK 补丁。

实际编辑期间，IDE 在 11:10:33 记录过一次 JSLanguageServiceQueue 的 200 ms signatureHelp 超时（对应服务请求约 347 ms），随后参数显示与跳转恢复。将其记录为 EAP 验收中的真实异常，不把编辑体验写成“完全没有 IDE 错误”。本轮没有修改 IDE 的超时设置。

## 研究阶段建议（保留对比，已被上节修正）

研究阶段曾优先考虑“共享运行实现，保留属性专属接口声明”。同名 class/interface 合并让每个属性保留参数类型、中文说明与属性文件中的定义位置，真正执行的方法由少量普通基类提供。保留 new Css()、s.width.px()、s.color.rgb() 等现有写法，不使用 Proxy、运行时拼接原型、SDK 补丁或额外入口。

该方案在最小 new Css() 消费夹具中使压缩 JS 减少约 20.3%，gzip 减少约 6.3%；单属性或少量属性消费的 gzip 收益很小。不能把代码体积差异说成运行速度提升。

## 实际分类

当前 502 个属性作者正好分为五组：

| 分组                | 属性数 | 候选基类                  |
| ------------------- | -----: | ------------------------- |
| 普通属性            |    247 | CssProperty<V>            |
| 普通属性 + 数学方法 |     51 | MathCssProperty<V>        |
| 长度 + 数学方法     |    162 | LengthCssProperty<V>      |
| 颜色                |     27 | ColorCssProperty<V>       |
| 长度 + 数学 + 颜色  |     15 | ColorLengthCssProperty<V> |

全部长度作者当前都具有数学方法，因此 LengthCssProperty 可以继承 MathCssProperty。颜色格式方法在 ColorCssProperty 和 ColorLengthCssProperty 各保留一份，不引入动态 mixin。候选中的这些基类属于包内部，不新增包根 API。

原先 502 份 raw、228 组数学方法（每组 4 个）、42 组颜色方法（每组 4 个），共 1,582 个重复方法实现，候选归并为 13 个：1 个 raw、4 个数学方法、两组各 4 个颜色方法。单位和 Grid 方法没有改写。

## 隔离实验

实验副本位于 test-results/css-method-research，未改工作区正式源码；目录内 run.mjs 生成/构建候选，validate.mjs 检查类型和语言服务，semantics.mjs 对比输出。原始结果为 results.json、validation.json、semantics.json。这些是研究时的本机快照，不进入发行包和正式构建；脚本依赖当时的生成模板，不作为持续维护的通用基准命令。

## 验证证据

四个版本均通过：

- 现有 36 个 CSS 焦点测试；未修改或放宽原测试断言。
- 现有 CSS 类型夹具、项目继承示例，以及额外颜色/长度/数学方法反例。width.raw(123)、width.min(2)、color.raw(123) 仍报类型错误；opacity.clamp(0, 0.5, 1) 有效。没有向 color 开放 px，也没有向 display 开放 clamp。
- 官方 TS7 原生语言服务对 width.raw、width.clamp、opacity.clamp、color.rgb 的补全、中文 hover 和定义响应。
- 全部 502 个属性的可用方法集合、12,586 个关键字声明及可用目标方法的示例输出一致。
- 自定义 ColorCss.raw 覆写后，rgb/oklch 继续调用该覆写方法。
- 使用实际框架编译器编译同一 TSX，并经真实 SSR 渲染器运行；安全颜色/宽度变量和 inherit 回退两种输出与基线一致。

接口候选方案四个抽查方法的 hover 文本与基线逐字相同。定义仍指向 u-z.ts、m-o.ts、c-f.ts 中相应成员，但该位置现在是接口方法声明，实际执行体位于共享基类。这不等于在 WebStorm 中完成了真实鼠标/快捷键跳转验收。

实验过程中发现：共享方法的 JSDoc 如果紧跟在 class 左花括号同一行，SDK 声明生成会丢失该方法注释。候选将注释放到独立行后，原中文文档测试通过。正式生成仍应先格式化再编译，并保留此验收。

## 实施时的边界

1. 生成器仍是唯一维护来源：方法签名、文档和实现从同一份方法描述生成，避免维护两套模板。
2. 只在 generated 内调整；不增加新的 src 顶层文件或目录，保持 runtime/generated/util 和唯一 index.ts。
3. 保留属性专属方法类型与中文说明；泛型 V 不放宽为 string | number 后再回填。
4. 共享方法改变了原型层级和函数身份，正式迁移继续验证自定义作者、覆写、元数据识别与参数求值顺序。
5. 正式迁移后还需验证真实 UI 构建/浏览器行为、独立发行包消费，以及 WebStorm 实际补全与跳转。本研究未执行候选的完整框架平台/浏览器矩阵，也未测得可归因的页面运行速度提升。
