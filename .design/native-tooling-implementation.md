# 原生工具共享实施

2026-10-06 用户批准优化，随后要求进入生产可用目标模式，以适当测试和取舍逐步决定范围，不预先锁定完整方向。当前候选是共享项目服务与检查调度、少量类型规则、import 操作和框架修复建议、包边界与公开声明检查，以及独立的 Go 格式化试验入口；只有通过正确性、成本与生命周期验证的部分才进入默认工作流。

## 实施约束

- 沿用固定 TS7 和现有 native 包，不恢复传统编译器或引入通用 ESLint 兼容层。
- 服务持有一个 Go LSP/API 进程；自有 CLI、Vite 和 MCP 通过项目级连接复用它。文件版本、快照与客户端所有权明确，断开不误杀其他客户端，空闲服务可退出。
- Go 类型规则接在已有 checker 的诊断过程；规则输出同时进入 CLI/API/LSP，不在 Node 中重新建树或复制类型系统。
- import 与格式化复用上游 LSP；编辑包含原始内容校验，避免覆盖已变化的文件。框架修复只处理明确可修复的错误，其余给出建议。
- 公共 API 与包边界读取同一原生项目的声明和模块信息。API 报告提供可审阅的差异，不把文本变化等同于语义兼容证明。
- 保留现有 Prettier 默认入口；Go 格式化作为显式试验命令，WebStorm 自动格式化尚不切换。
- WebStorm 自行启动的服务不自动并入自有共享进程，保留明确的接入验收边界；不以同一 SDK 路径冒充进程共享。

## 验证

覆盖跨客户端复用、文本隔离、依赖更新、配置变化、错误修复、关闭与重连；类型规则检查 Promise、分支类型及假阳性边界。运行原生语义、CLI/Vite/MCP、编辑和声明报告测试，保留原有框架验收。比较同一输入的独立与共享请求，记录进程、项目缓存命中和检查次数；完整六平台与三浏览器交给 CI。

## 测试后的取舍

- 五包采用一次原生项目引用构建，移除其后重复的包级类型检查。一次性 CI 检查仍直接使用 Go CLI；主示例加工具配置单轮首次检查直接约 24.0 秒，共享约 37.6 秒，不能为了统一入口引入冷启动退化。
- 连续请求使用工作区服务；相同文本第二客户端命中同一编译缓存，六个客户端共用一个 Go 进程。检查缓存额外核对依赖文件指纹与配置文件列表，文件增删和失败恢复有实际回归。
- 实测后修复 Windows 删除目录时的自重命名监听循环、Vite 目录外源码被拒绝、Promise 赋值误报，以及单文件修复可能丢弃其他文件编辑的问题。
- core 公开报告约 571 KB，保留为按需审阅；原生排版与 Prettier 输出不同，保留试验入口，不切换默认格式化。
- 同步单文件转换、一次性 CLI 与 WebStorm 有各自进程；不同编译选项可能需要不同 Program。不把共用 SDK、同一进程与同一 AST 混为一谈。
