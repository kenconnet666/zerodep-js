## 本轮范围

- 沿用现有 Node broker 与定制 Go LSP/API，不增加操作系统启动服务。按工作区、SDK 和适配代码版本隔离；增加可配置空闲时间、会话保留、有限缓存和显式停止能力。
- 完整检查优先使用原生增量构建状态，但必须保持不产生 JS/声明输出、不覆盖用户 build-info、不漏配置/包元数据/根文件增删导致的错误。特殊配置先保留完整检查路径，依测试再决定是否优化。
- 由原生解析有效配置并读取依赖；synthetic Program 使用原生返回的 pathsBasePath 修正继承相对 paths 的基准。磁盘编译状态可跨客户端保留，虚拟文本保持客户端独占。重新使用缓存前核对磁盘和配置，不能只依赖监听通知。
- 不合入研究用的隐式 JSX 导入裁剪、绑定捷径或索引实验。WebStorm 保持当前受支持的独立 LSP 路径，不用尚未验证的多客户端代理替换它。

## 验证和取舍

先验证 noEmit 增量选项、错误/修复及配置路径，再接入默认检查。增加依赖错误、声明变化、缺失模块恢复、元数据、缓存损坏、多客户端重连、空闲释放和显式停止回归。保持已有失败断言，不通过等待文件监听事件掩盖失效问题。

本地运行原生专项、工程检查、构建、LSP 和真实消费相关检查；六个平台及完整浏览器矩阵交给既有并行 CI。记录冷/热、实际修改与失败恢复的性能，不把无变化缓存当作编辑速度。
