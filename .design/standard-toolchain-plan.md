# 官方 TS7 与标准 TSX 工具链简化方案

日期：2026-10-07。状态：用户已授权进入目标模式执行。当前开始关键工具验证，尚未完成迁移；既有交接和已发布版本的验收不代表新路线通过。

用户本轮确定的优先级：简单、方便维护、方便使用、良好的类型提示和适当中文注释是核心；性能不是最重要的。优先广泛使用、人工易维护的依赖，保留好用的框架 API，通过成熟工具和集中实现降低维护成本。已明确使用官方最新 TS7.1 dev 与 Vite，面向以后成熟的 TS7.1；接受官方接口变化时继续适配，不再评估或退回 TS6。

中文注释集中解释不明显的语义、取舍、资源所有权和生命周期边界；不复述代码，不通过过度压缩实现减少行数。类型提示验收覆盖补全、泛型推断、悬浮信息、错误位置、导航与重命名，不仅检查 tsc 的退出码。

已确认的 API 方向：保留 DOM 与组件 bind、bind:this，以及 `_component(({ title = '标题', ...rest }: Props) => ...)` 的响应式参数解构、别名、默认值和实时 rest。普通属性/事件、props 参数及 ref 回调继续可用，不作为替换上述写法的迁移要求。不得以迁移工具链为由预先删除或降级这些能力。

必须参考 Svelte 的实际源码，区分不可妥协的正确性过程和可以做得更简单、更好的实现。已据本地 Svelte 5.56.10 / 15720b16a5ef33e3e1f4301c77b94ec375070e73 重新核对。绑定类型检查等在官方 TS7 下的实现仍待验证；“API 保留方向已确认”不等于“迁移方案已验证完成”。

本轮重新取舍的对象主要是内部机制、工具分工和新增范围，不重新否定已确认的 bind 和解构写法。第 7 节给出逐项采用、限制与暂缓决定；不是将 Svelte 的全部功能和内部架构搬入本项目。

## 1. 推荐目标

采用官方最新 TS7.1 dev、Babel 框架插件、Vite、Oxlint/tsgolint、Prettier，以及现有 Vitest/Playwright。框架保留显式变量式响应性和自身运行时，不引入 React 运行时或改成 `.value`。

- 官方 TS7.1 dev 负责类型检查、声明输出和标准语言服务；可使用其官方 unstable API。每阶段核对最新 7.1 dev 并固定精确版本和锁文件，不让安装静默漂移；只维护选定版本，不维护内核补丁或多版本兼容分支。
- Babel 负责解析、作用域、遍历、节点构造、代码生成和 source map；自有插件仅实现框架分析与转换，不自造 parser、printer、模块解析或类型系统。
- Vite 负责模块图、文件监听、开发服务器、资源、打包及更新通知。插件只接转换与必要生命周期，不再持有 TS 编译服务、文件指纹和项目缓存。
- 通用 lint 优先 ESLint 正式支持的 TypeScript 接入，不因为 Rust/Go 的速度选型。2026-10-07 实查 eslint 10.12.0、typescript-eslint/parser 8.71.1 的 TS peer 为 >=4.8.4 <6.1.0，尚不支持本轮 TS7.1 dev，因此当前保留已有 Oxlint；tsgolint 仅作为通用类型规则候选，不扩张自有 Go lint。正式支持后优先切换 ESLint，不为其引入 TS6，也不绕过 peer 限制宣称兼容。框架分析与 lint 宿主分离，避免绑定到替代工具的私有接口。
- Prettier 负责格式化。内置 parser 能覆盖当前源码与格式结果时，优先用内置能力减少配置；现有 Oxc 插件不因“性能不重要”就自动删除，先比较格式差异和维护收益。专属缓存包装列为整理候选，不同时引入 Oxfmt/Biome。
- 保留 Node 24、项目固定 pnpm、catalog 和 workspace 依赖方式。

执行基线采用 2026-10-07 核对的官方 next：`7.1.0-dev.20261006.1`。官方 CLI/LSP/API 都可按需使用，将接口适配集中在工具层，避免 API 变化扩散到运行时。未来官方接口变化继续适配，成熟 TS7.1 发布后切换同一维护线。

### 版本评估历史与最终决定（2026-10-07）

本次 registry 查询：typescript latest 为 7.0.2，6.0.3 仍可获取；工作区实际依赖和已安装包仍为 7.1.0-dev.20261005.1，WebStorm 配置指向项目定制 SDK，并未切换到上述候选路线。

官方 TS7 的普通检查、声明及基础语言服务可用，不代表传统 Compiler API、tsserver 插件和全部第三方工具已经兼容。typescript-eslint 当前官方支持范围为 >=4.8.4 <6.1.0；Oxlint/tsgolint 是 TS7 路线的现成选择，但其自定义 JS 规则不能直接访问 TS 类型信息。本机 7.1 nightly 的编程入口仍标记 unstable，不能当作成熟稳定 API。

按本项目优先级，TS6 的传统 Compiler API 和既有工具生态是有实际价值的候选，值得比较框架检查与 WebStorm 适配的实现量；不能仅因 TS7 性能更好就排除。TS6 语言服务插件同样不改变普通 tsc 的类型语义，也不会自动解决 bind 隐式赋值和控制流；必须复用相同负例和真实编辑器场景验证。

最终决定：用户明确选择官方最新 TS7.1 dev，接受后续接口适配，TS6 比较在此结束。上文保留当时的生态核对事实，不作为继续降级或维护双版本的执行建议。

依据：[TS7 官方 API 边界](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)、[typescript-eslint 支持范围](https://typescript-eslint.io/users/dependency-versions/)、[Oxlint JS 插件限制](https://oxc.rs/docs/guide/usage/linter/js-plugins.html)、[传统语言服务插件边界](https://github.com/microsoft/TypeScript/wiki/Writing-a-Language-Service-Plugin)。这些是资料与本地配置核对，尚未完成两种稳定版本的项目级对照验证。

## 2. 标准 TSX 的边界

源码保持普通 `.ts`/`.tsx`，使用标准 import、变量、函数、泛型、JSX、事件回调和类型声明；不增加自定义文件扩展名或 parser fork。

标准 TSX 语法不等于普通 JS 运行语义。`_state` 的读写、`_derived`、动态 JSX、组件边界与实时列表参数仍需框架转换。未经过插件时宏明确失败，不能伪装成普通 JSX 转译即可运行。

保留目前 isolatedModules、verbatimModuleSyntax、erasableSyntaxOnly 等适合独立转译的约束；不承诺所有历史 TS 扩展语法都进入框架支持范围。泛型、satisfies、类型导入等标准用法须通过真实消费测试。

围绕已确认保留的 API，验证官方 TS7 的检查接入。编译与检查分工不等于拒绝框架检查层：原始 TSX 不能表达的隐式写回，可以研究局部检查代码和位置映射，优先复用现成依赖。普通 tsc 和语法 lint 不足以证明这部分安全；不以“不建语言工具”为硬限制，也不预建完整虚拟项目平台。若确有无法合理实现的具体阻碍，先报告证据、保留成本和替代方案，再与用户讨论；不得过滤真实错误、删除 API 或留下类型安全缺口来绕过阻碍。

## 3. 已确认保留的 API 与实现要求

### 保留

- `_state`、`_state.raw`、`_derived`、`_derived.by`，以及普通变量读写。
- `_component`、泛型组件、响应式参数解构、别名、默认值、实时 rest、children、key、受控输入、ref 回调。
- DOM `bind:value`、`bind:checked`、`bind:valueAsNumber`，现有组件 `bind:*` 和仅 DOM 的 `bind:this`，保持已声明的支持范围。
- `For` 的 key 身份和实时 row/index；不能用普通 map 重跑替代而改变身份或资源生命周期。
- effect、cleanup、context、快照、history、lazy、路由和存储的现行职责。history 当前位于 use/history，不恢复已删除 core 入口。
- `_mount`、`_hydrate`、SSR、错误边界及实际表单/IME/reset 行为。
- HTML/SVG/MathML、原生事件、class/style、已有 `on:*`/`oncapture:*`/`prop:*`。命名空间属性属于标准 TSX 语法，仅因外观不改名；不再承诺通过 TS fork 修复其编辑体验。

### 保留 bind，分别实现和验证各类绑定

Svelte 将固定 DOM 绑定、组件可绑定字段和 bind:this 分开分析与生成。我们沿用这种职责划分，简化内部实现，保留用户写法：

```tsx
<input bind:value={name} />
<input type="checkbox" bind:checked={enabled} />
<input type="number" bind:valueAsNumber={amount} />
<Editor bind:value={name} />
<input bind:this={input} />
```

| 类别         | 实现和验收要求                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 原生表单绑定 | 使用明确的标签、属性、事件和写回规则；复用已有受控输入流程；保留数值空态、多选、IME、选区和 reset 行为                      |
| 组件绑定     | 保留现有 value/onValueChange 等属性与回调的公开约定和 bind 推导结果；可以整理内部类型表达，不新增强制声明或要求用户改写调用 |
| bind:this    | 保留仅 DOM、简单可写变量、挂载赋值和卸载清为 undefined 的范围；解决真实元素写回方向及延后赋值的控制流检查                   |

所有绑定均须检查目标可写性、写回类型和属性冲突。数值输入继续将 NaN 归一为 undefined；多选继续写回字符串数组；绑定与用户事件并存时保持原有写回顺序。bind:this 的旧节点清理不能清除新节点引用，SSR 不写 DOM 引用，hydration 成功后才激活。

原始 JSX 属性的读取方向检查不能证明隐式写回安全。官方 TS7 下的检查与编辑器接入属于迁移必须解决的工作：用不可写目标、类型过窄目标、错误 DOM 类型、不接受 undefined、回调内错误收窄等反例验证，不仅验证运行效果。

普通属性与回调、ref 仍用于显式事件处理和复杂资源初始化，与 bind 并存。需要引用变化驱动视图时仍显式 `_state`；不隐式赋予普通 let 响应性，也不要求用户引入新的 ref 容器、model 容器或 bindable 类型 DSL。

### 保留响应式参数解构、默认值和 rest，集中实现

Svelte 用编译期绑定信息，把解构读取转换成 getter 或属性读取；fallback/rest 由集中 runtime helper 承担。当前 zerodep-js 的 prop/restProps 也已有这一边界，应先移植和简化这条路径，不能因为发生转换就认定 API 太重。保留当前浅层解构、别名、默认值和 rest 范围，不自动扩展嵌套解构。

以下写法继续作为正式支持的组件 API：

```tsx
const Card = _component(({ title = '标题', ...rest }: Props) => (
  <section {...rest}>{title}</section>
));
```

这是标准 TSX 中的函数参数解构语法，由框架转换赋予其明确的响应式语义。title 持续读取最新 prop，rest 保持排除已解构字段后的实时只读视图；无需用户到处改写 props.title。

默认值只针对 undefined，不能用 ?? 改变 null 的处理。编译器和运行时负责维持当前默认值的惰性求值、实例隔离、缓存、依赖更新及对象/函数身份；不能要求用户手工搬出默认对象来弥补迁移后的语义退化。

编译器只维护宏绑定分类和引用替换，别名、默认值及实时 rest 的共享行为集中实现；能直接读取的 prop 不强制生成多余派生。普通局部解构继续保持 JavaScript 快照语义，不能扩大隐式响应范围。前向引用和只读约束仍给明确诊断，不静默改变语义。属性转发保留源顺序、新增/删除键和正确覆盖；不预建通用 props 工具包。

单个 props 参数继续可用，不要求为保留解构而增加新的强制类型包装。Readonly 只提供浅层类型约束；参数绑定的只读规则和运行时已有 props 所有权保护仍由框架保证，不解释为深度冻结。

### 优先组件边界内安全重建，分开评估状态保留

本地 Svelte HMR 通过稳定包装、组件函数 source 和受作用域管理的 branch 完成更新，替换时销毁旧 effect，并避免重复包装不断累积。先验证类似的局部组件重建能否复用我们现有生命周期；整页刷新只作为无安全边界时的显式后备。CSS 等普通资源继续走 Vite 原生更新。

当前兼容声明的状态保留先作为既有契约记录，与旧 effect 必须销毁、错误后能恢复分开验收。若轻量重建不能保留本地状态，明确展示体验与代码差异后讨论是否撤回状态迁移，不能在换编译器时顺手删除。读过本地 HMR 文件不等于证明 Svelte 全部更新场景都保留或丢弃状态。

不通过缺少清理的模块替换实现伪 HMR，也不能声称 Vite 自动提供框架状态保留。

现有显式 _inspect 面板与编译注入耦合单独盘点：可独立复用部分保留，依赖编译元数据的部分同步适配；只有对应元数据实际获准删除后才简化消费者，不在本次新建 Devtools 平台。

## 4. 编译、检查和产物

运行链路固定一条：原始 TSX -> Babel 框架转换和官方类型擦除 -> JS/map -> Vite 后续处理。应用与组件库使用同一转换器，CSR/SSR 复用相同运行时协议。配置顺序须确保框架识别在 JSX 被通用工具降低之前完成。

源码类型检查与声明输出使用官方 TS7；普通运行时包可由 tsc 构建，含框架宏的源码不能把未经 Babel 的 tsc JS 当成可执行产物。组件库声明从用户类型边界生成，内部 helper 不泄漏到公开签名。

推荐检查分工：

- 应用：官方 tsc --noEmit + 全项目框架规则 + Oxlint。
- 发布包：官方声明构建 + 同样的框架规则 + JS 构建与独立声明消费。
- 开发：Babel 即时报告框架错误，官方 TS7 语言服务提供类型反馈；不在每次 Vite 转换中建立全项目 checker。
- 通用类型 lint：no-floating-promises、no-misused-promises、switch-exhaustiveness-check，配置与原规则逐项比较。

上述分工不是宣称原始 TSX 的 tsc 加语法规则就已经覆盖绑定类型：框架检查入口还必须承担 bind 写回的已确认验收。优先尝试将有限的绑定关系表达为官方 TS 可检查的代码；泛型组件、readonly 对象属性、联合类型、局部控制流和声明输出必须一起验证。普通类型检查仍由官方 TS 执行，不在 Babel 中实现可赋值性算法。该适配是否可同时满足 CLI 与 WebStorm，是阶段 2 的决定性验证，尚无完成结论。

首先保持 tsc 作为类型验收来源，Oxlint 不重复开启完整 type-check。后续若合并应用检查，必须验证 tsgolint 和所选 TS7 的语义版本及诊断一致性。tsgolint 不是天然共用 tsc 的进程、Program 或缓存。

保留宏合法性、只读派生、跨模块绑定、延迟读取收窄等必要源码规则。TSX 中的每个框架错误不能只在被 Vite 导入后才发现，全项目检查必须遍历未被当前入口引用的受支持源码。

## 5. 编辑器和框架诊断

官方 TS7 提供标准补全、导航、重命名、类型错误；Prettier 提供格式化；Oxlint 官方编辑器接入提供 lint。

Oxlint JS 插件支持语法/作用域规则和编辑器诊断，但不能直接访问 TS 类型信息。先做很小的适配试点：复用 Babel 框架分析返回的诊断，允许为此重复解析，不为性能复制一套规则或统一两套 AST。

试点需验证未保存文本、文件新增删除、Unicode 定位、重复诊断、配置隔离、WebStorm 和命令行一致性。若现成适配失败，记录具体缺口，再评审保留小型桥接；不直接扩张为完整语言服务或偷换成仅构建时才报错。

当前 MCP 工具的需求单独盘点。可保留必要的官方 LSP 只读转发，但移除定制 SDK 查找、内部 AST/API 协议和专属工具生命周期；不以“MCP 可调用”冒充 IDE 接入完成。

## 6. 目录与依赖精简

目标发布包按实际职责收敛为 core、use、ssr、compiler、vite。compiler 替换 native，名称和发布入口在实施阶段统一确认；lint/检查适配优先作为其子入口。五包是当前职责划分的结果，不是硬性指标；必要工具若确有独立依赖或生命周期再拆包，不能为了少一个包强行耦合运行时与编辑器。

建议删除或替换：

- native 包及六个自有平台包、Go 源码、上游补丁和定制 SDK 构建分发。
- 原生会话/API 协议、项目缓存、指纹、专属 TS CLI 包装。
- 移除依赖私有 checker 的 JSX 声明生成方式。参考 Svelte 的清晰标签/属性接口，比较维护阶段生成与直接类型表达的可读性；不为了“删除生成文件”恢复难读的通用条件类型。允许小生成脚本，只要不依赖定制 SDK，人工维护入口和数据来源清楚。保留严格类型反例，不用宽泛 any 提速或省事。
- 定制原生基准、SDK 验收脚本和旧平台产物管理；格式缓存另行核对是否可以直接使用 Prettier 标准能力，避免顺带引入全仓格式噪音。
- 已被替代的原生工具内部入口及其专属实现与测试；框架 API 的功能测试迁移到 compiler，bind 与解构相关正反例必须保留，不通过 mock 保留原生外观。

保留原生 HTML 属性数据依赖、csstype、source map 库等确有职责的成熟依赖。接受工具重复解析；不为“依赖少”重新实现 glob、映射、配置加载或 AST 工具。既有禁止引入的依赖仍遵守当前约定，选版本时审计直接及间接依赖。

不同时替换响应式调度器、DOM renderer、路由或持久化。通用 signals 包并不自动匹配现有深层代理、作用域和 SSR 语义，缺少明确收益时保留已验证实现更省维护。

## 7. 适当参考 Svelte 后的具体取舍

选择标准是：能否减少独立规则和生命周期责任，能否复用成熟依赖，是否保持既有 API 与行为。代码行数、包数量、少一次解析或微基准不是单独的采用理由。

| 领域               | 取舍                         | 对本项目的具体安排                                                                                                                                                   |
| ------------------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 编译分层           | 采用 Svelte 的分析与生成分工 | Babel 承担语法树和作用域基础；框架分析只记录宏、组件、props、绑定和诊断；生成阶段消费同一分析结果，不再另写 binder 或复制跨命令项目服务                              |
| props 解构         | 保留 API，采用集中 helper    | 复用现有 prop/restProps 边界，正确区分默认值、别名、rest 和普通局部快照；不把 Svelte 的 legacy/可写 prop 分支一并搬入                                                |
| props 读取优化     | 按语义需要取舍               | 不以“按需生成”为由贸然去掉当前缓存；JSX 属性中的函数调用、对象创建、getter 必须保持既有求值次数和身份。先用统一清楚的路径，确有收益再分静态/动态快路径               |
| 原生 bind          | 借鉴固定规则表               | 明确标签、模型属性、事件、值转换、冲突与 SSR 行为，减少分析器和运行时重复散落的规则；只覆盖现有表单和 DOM 引用范围，不扩充媒体、尺寸、窗口等绑定全集                 |
| 组件 bind          | 保留现有 props/回调约定      | 不照搬 $bindable，也不引入双向可写 props 所有权。调用处仍用 bind，内部仍走显式回调，类型声明保留现有支持结果                                                         |
| bind:this          | 保留限定范围                 | 借鉴引用身份和销毁顺序，复用 ref；不扩展为组件实例、动态索引和任意对象路径。官方 TS7 写回与控制流检查先通过试点                                                      |
| 表单运行时         | 保留必要复杂性               | 延续现有受控输入、IME、选区、reset、多选与接管前编辑的统一流程；不为 bind 另建一套表单 runtime，不机械复制 Svelte 不同的 reset 或空值约定                            |
| 列表、分支和作用域 | 保留行为，复用现有实现       | 同 key 替换数据、节点重排、焦点、子作用域清理必须继续正确；不为方便用整列表重建替代，也不直接引入 Svelte 的异步分支/转场调度                                         |
| HMR                | 借鉴稳定包装与可靠销毁       | 先把更新边界、卸载和错误恢复集中，再整理现有状态保留代码；不预先删除状态保留，不扩张到任意外部资源或整个组件树恢复                                                   |
| 类型与编辑器       | 接受必要的专属薄层           | 标准语法消除了自定义 parser 成本，但不消除框架检查。类型来自官方 TS7，框架关系由最小适配表达；不能声称 Svelte 编译能处理绑定就意味着我们的 TSX 可直接由 tsc 完整检查 |
| DOM 类型和生成     | 选择更清楚的维护入口         | 参考 Svelte 明确接口和标签表；成熟属性数据、csstype、有限生成脚本可以继续用。不把 generated 文件一律删除，也不堆通用条件类型来压缩声明行数                           |
| 工具替换范围       | 分阶段、按收益替换           | 首先退出私有 TS 与原生分发；保留已有可工作的格式化、测试、路由和存储工具，确认替代收益后才改，不借迁移同时换遍依赖                                                   |

固定绑定规则表表达有限平台事实，不承担 JS 赋值类型系统，也不建立一个能描述任意指令的新 DSL。静态可确定的非法用法由分析器报错，来自 spread/动态输入的约束继续在运行时验证。

可以做得更简单的地方：我们只支持一套显式变量式 API，没有 Svelte legacy 模式、SFC/CSS 编译和兼容组件类的责任；可以保持只读 props、显式回调、统一 undefined 空引用、同一 CSR/SSR 协议。这里减少的是无关范围，不能据此推断所有 runtime 分支都多余。

保持暂缓：深层响应式参数解构、动态路径 DOM 引用、组件实例引用、媒体/窗口绑定扩展、流式 SSR、隐式跨 await 跟踪、完整 Devtools 时间线、跨宿主常驻服务。它们并非本轮已确认功能，不因 Svelte 存在相应实现就加入迁移。

### 先验证最难的边界，再迁移普通代码

阶段 2 首先验证以下四组；失败时继续研究实现路径并记录具体阻碍，不先批量重写编译器或删除旧 SDK：

1. **绑定检查：** DOM/组件 bind 的写回方向，const/readonly/派生目标，字面量联合与泛型组件，bind:this 的元素类型、undefined 和回调收窄；确认声明消费与编辑器表现。
2. **解构语义：** 默认表达式有无依赖、对象/函数身份、undefined/null 切换、前向引用、rest 新增删除、spread 覆盖和最新回调读取。
3. **生命周期：** 同 key 换对象、重排与焦点，旧引用清理不覆盖新引用，SSR 不运行客户端 effect/ref，接管前输入不丢失。
4. **开发反馈：** 未保存源码诊断、映射、跨文件重命名，以及 HMR 错误修复后恢复、旧资源释放、现有可保留状态的范围。

试点结果分别标注“源码依据”“本项目已有回归”“新路线实测”。Svelte 源码支持一种思路，不代表新路线已通过。性能数据只辅助定位异常和防止无法使用，不作为放弃可维护依赖的理由。

## 8. 实施阶段与验收

1. **冻结不可退化行为与记录基线。** 将 bind 和响应式参数解构的保留要求写入验收矩阵，按下节 Svelte 源码证据评审内部实现及 HMR 方案，不重新把已确认 API 当作删减候选。清点当前未提交工作和交接边界，保留已有改动，不从旧提交覆盖工作区。性能只记录是否可用，不设竞速目标。
2. **小范围工具验证。** 先执行第 7 节的四组关键验证，再验证同一真实 TSX 场景。工具选型不等于适配已完成；只有 CLI、声明和 WebStorm 的关键路线成立后才批量迁移，未解决的检查问题记为阻碍，不通过删除 API 或断言完成验证。
3. **建立唯一框架分析与转换。** 先核心变量/JSX，再 props/For/SSR；已有语义测试直接调用新实现。迁移期间暂存旧路线仅供受控对照，完成后删除，不发布双后端。
4. **迁移工具接入与消费工程。** 更新编译器包入口、构建配置、类型、文档和外部消费夹具，保留示例中的 bind 和解构写法。人工复核默认值身份、rest 更新、绑定事件顺序、数值空值、多选和引用清理是否等价。只有另行讨论确认的 API 调整才进行 AST 迁移，不夹带批量改写。
5. **接入构建和编辑器，移除原生基础设施。** Vite、独立组件库、官方 TS7、lint、格式化和必要 MCP 转发完成实际消费验证；再删除补丁、平台包及无用配置，保留研究记录和用户 IDE 配置。
6. **验证和发布候选。** 本地运行变更相关检查；CI 并行工程检查、三浏览器、Linux/Windows 干净安装，macOS/ARM 保留有意义的安装与生命周期 smoke，不再自建六个平台编译器。更新发布清单，固定 tgz 和注册表验证，完整门禁通过后才交付候选。

每个实施阶段形成中文、可审阅提交并推送；推送前查看上一轮 CI，推送后不空等。现有未提交改动按交接内容保留和验证，阶段提交明确边界，不把历史通过结果或新规划当作迁移完成。

验收至少包括：只安装官方依赖即可构建；不依赖本机定制 SDK；标准 TSX 能由官方工具解析；泛型、声明、事件 currentTarget 类型有效；框架负例被报告；浏览器 IME/reset/焦点、For 身份、SSR 接管、清理行为仍正确；开发更新的实际状态保留/重置边界已验证并明确记录；生产依赖图不包含 Babel/TS/lint；工作区外应用与预编译组件库可真实消费。

## 9. Svelte 源码依据与不可妥协的过程

本轮实际阅读的是本地 Svelte 5.56.10，提交 15720b16a5ef33e3e1f4301c77b94ec375070e73。以下路径相对其 packages/svelte/src；结论针对该快照，不冒充最新版本行为或已经执行的差分验证。

| 阅读位置                                                                    | 源码所体现的责任                                                                  | 本项目的行动                                                                                               |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |

必须保留的测试契约：

1. 每个响应式订阅和外部资源有明确 owner；重跑、分支切换、卸载及异常都正确清理，不跨 await 偷带作用域。
2. 编译重写保持 JavaScript 求值次数、顺序、短路、自增返回值、闭包及变量遮蔽；不能只看计数器输出。
3. props 默认值、rest、spread 和回调读取保持实时性与身份约定；初始化快照与动态读取边界明确。
4. 控件输入、IME、选区、数值空态、reset、多选及 hydration 前编辑是用户可观察语义。
5. keyed 列表同 key 更新数据而保留实例，换 key/删除可靠清理；SSR 请求隔离、转义和接管不能降低。
6. 可解析的 TSX 不等于框架合法；泛型、只读/写回负例、诊断位置、声明消费、编辑器真实操作必须验证。

参考方法：为每项建立“本项目契约 -> Svelte 源码与相关测试 -> 采用/不采用原因 -> 项目回归用例”。只对双方语义相同的场景做差分对照。Svelte 的 legacy、双向 props 所有权、组件实例、异步/转场和 null 清理并非本项目必须复制的范围；本项目仍遵守 readonly 派生和 undefined 引用清理等现行契约。引用代码或移植片段时记录来源并遵守许可证，不依赖 svelte/internal 私有接口。

## 10. 修订后的取舍结论

保留 bind 和响应式组件参数解构等现有好用的框架 API，优先删除通用工具的重复实现和 TS 内核维护，把必要框架逻辑集中到 Babel 分析与少量生命周期 helper。绑定按类别实现和验证，HMR 先研究局部正确重建。允许转换较慢和重复解析，不因不追性能而放弃类型检查、幂等写入、身份保留等正确性。

不通过减少真实类型检查或把框架语义排除在验收外来达成“小核心”。若验证发现具体能力无法在选定工具下合理实现，必须先给出可复现阻碍、保留成本、替代方案和实际行为差异，再与用户讨论；不得自动删除、降级或把调用方改写当作既定解决方案。目标包由十一包收敛为五包的建议不变，但不把删包或行数当成维护收益的唯一证据。
