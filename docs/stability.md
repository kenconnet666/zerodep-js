# 稳定性验证与观察基线

本页记录可重复的生命周期、GC 和请求隔离验证。它们用于发现资源残留与回归；包大小、运行速度和堆增量没有固定发布阈值，验证耗时也不冒充纯渲染吞吐或框架性能排名。

## Node 工作负载

```sh
pnpm test:stability
pnpm test:stability --iterations 5000
```

命令构建真实包产物后启动带显式 GC 的独立 Node 进程。默认本地每组 1,000 轮，CI 每组 5,000 轮，包含：

- 共享 source、两级派生、动态依赖、DOM/property/effect 阶段的重复创建和销毁。销毁前留下排队任务，检查任务撤销、cleanup 次数、订阅解除及作用域可回收。
- 长期存活字典上的临时字段查询，分别读取值与存在性。查询结束后键可回收，实际对象始终不含这些字段；仍存活的冷派生保持缓存身份，后续更新和重新订阅正确。
- 清理函数失败后，其余清理和独立根继续工作；已经撤销的任务不能迟到执行。
- 异步加载步骤交错后的同步 SSR 请求，验证 context 隔离、错误恢复、清理、服务端不运行 effect，以及请求作用域可回收。

报告位于 `reports/stability/stability-node.json`，与 Playwright 产物分开，避免浏览器测试初始化清空 Node 报告。CI 同时保留报告和验证日志。

## 浏览器工作负载

```sh
pnpm build
pnpm exec playwright test tests/e2e/stability.spec.ts --project=chromium
```

真实 example 入口提供根外的“重新挂载应用”按钮，卸载后也可恢复应用。测试用同一入口反复替换整棵应用，覆盖动态列表、控件、property 和自定义元素；CSR 与 SSR 首次接管各自验证。本地每种模式 40 轮，CI 每种模式、每个浏览器 200 轮。

每轮在卸载前留下组合输入结束、表单 reset 等延后工作。卸载后再派发旧按钮事件，确认它不能通过旧回调误销毁新根；随后请求 GC，检查旧节点和传给自定义元素的对象引用没有被保留。最后重新挂载并实际交互，确认后续应用仍可工作。

压力循环使用 DOM 事件派发，避免测试工具的鼠标命中检查持有旧节点；正常键鼠与输入交互由功能用例覆盖。GC 跨任务执行，给 WeakRef 保活期和最终回收回调留下实际任务边界，不用固定 sleep 代替清理验证。每次报告保存到测试输出中的 `stability.json`，CI 上传 `stability-metrics` 产物。

## 已发现并修复的问题

2026-10-01：长期存活的响应式对象在短期 effect 中查询新字段，即使 effect 已销毁、字段从未存在，原来的强引用缓存仍保留这些键。对 `bb1ca65` 的实现和修复实现执行相同的 500 次查询、五轮 GC，结果分别为残留 500 个键和 0 个键，对象实际字段均为 0。

字段缓存现使用弱引用，实际观察者和冷派生仍持有需要的依赖。旧缓存回收时检查条目身份，不能删除同名字段的新订阅。写入时仍使冷依赖版本失效，不用“清空全部缓存”牺牲派生正确性。

异常恢复检查还复现了 getter 抛错后的失效遗漏：在读到其他依赖前抛错，原实现没有登记这个字段，随后替换 getter 也无法使旧异常失效。失败读取现在同样记录依赖，回归用例验证冷派生和 effect 都可恢复。

本轮 Windows / Node 24.18.0 本地观察：

| 工作负载                    | 轮数  | 结果                                               |
| --------------------------- | ----- | -------------------------------------------------- |
| 依赖与作用域周转            | 1,000 | 2,000 次 effect 与 cleanup 对应，残留作用域 0      |
| 临时查询与冷派生            | 1,000 | 残留查询键 0，冷缓存身份与更新保持正确             |
| 清理失败恢复                | 1,000 | 其他 cleanup 和独立任务均完成                      |
| SSR 请求与降级              | 1,000 | 2,000 次 cleanup，残留作用域和服务端 effect 均为 0 |
| Chromium CSR / SSR 整根替换 | 各 40 | 各抽样 120 个节点/数据引用，残留均为 0             |

这证明上述工作负载下的结果，不是对任意应用、无限运行时长或全部平台输入法的证明。真实异步业务、实际设备输入体验、最终候选矩阵与发布流程继续按 [生产计划](production-plan.md) 推进。
