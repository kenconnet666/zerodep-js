## 待决策的精简方向

### 1. 缩小公共工具面

`_mergeSlotProps` 当前没有被成品组件调用，只由测试消费；`_composeEventHandlers` 由它及测试使用。`_observeSize/_observeFontSize` 当前用于测量示例和测试，尚无成品组件依赖。它们有独立契约和测试，不能仅凭仓库内无调用就认定无用。

建议下一轮明确这些能力是否供应用作者直接使用：若没有这样的需求，可将必要实现留在 internal，并删除不需要的公开导出、文档和专属示例；涉及公开 API，本轮不擅自移除。自动导出目录中的新增 export 也应按公共 API 审阅，私有辅助函数放 internal。

### 2. 收拢重复的浏览器 SSR 准备代码

buttons/grid/base/measurement 等测试重复读取 docs 服务端入口、HTML 模板和 CSS，并设置页面路由。可提取一个测试专用的 docs SSR 帮助函数，降低后续入口或样式协议变化时的漏改风险；各场景的 DOM 身份、无脚本首屏及接管断言应保留在原测试中。

### 3. UI 发布前单独验收类型入口

UI 目前以源码作为 types 入口、dist 作为运行时入口，以满足本地编辑体验。它仍是私有工作区包，当前可用；若准备对外发布，需先验证 tgz 包含范围、声明映射及工作区外的类型/运行时一致性，不能直接去掉 private 就发布。
