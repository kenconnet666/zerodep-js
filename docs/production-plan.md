## 1. 目标与当前状态

已确认的方向：

- 使用标准 TypeScript/TSX，类型基线为 TypeScript 7，不增加 TypeScript 5/6 兼容层。
- 状态显式声明，之后像普通变量一样读取和赋值，不暴露状态容器 `.value`。
- 组件支持直接解构 props，并就近使用默认值。
- API 简洁、职责明确，不为形式增加 model、controller、factory、通用配置对象等层次。
- 支持 CSR 和 SSR；生产版本还必须具备与 SSR 对应的 hydration。
- 参考 Svelte、Solid、Vue 的具体机制，依据本项目的 TSX、类型系统和维护成本做选择。

## 2. 完整生产目标与职责边界

生产版本面向现代浏览器与 Node 服务端，至少需要：

1. 变量式状态、纯派生、可清理副作用，以及可靠的依赖与生命周期管理。
2. 有类型的函数组件、响应式 props、默认值、children、事件和原生属性转发。
3. 文本、属性、条件、列表和动态组件的正确 DOM 更新。
4. 常见输入控件、焦点、选择区、IME 与组件销毁行为正确。
5. 同一应用的 CSR、SSR 与 hydration，保证服务端和客户端的语义一致。
6. 标准 TSX 编辑体验、可定位的编译错误、可用的 source map 和开发更新流程。
7. 可消费的包产物、版本策略、支持范围、文档和真实应用验证。

以下能力不默认成为生产版本的前置条件：内置路由、全栈数据层、RSC、流式 SSR、复杂 Suspense、动画系统、完整 UI 组件库、多个构建器适配、旧浏览器兼容。需要时单独确认，避免把生产可用扩大成无止境的功能清单。

## 3. 推荐 API 形态

以下主要 API 已有实现，执行语义以 semantics.md 为准。仍在本地开发的原生扩展会单独标注；模块拆分与命名可以依据实际职责调整，不为尚未发布的内部接口保留重复兼容层。

### 3.1 组件、props 与默认值

```tsx
import { component, $state, $derived } from 'zerodep-js';

type CounterProps = {
  initial?: number;
  step?: number;
  onChange?: (value: number) => void;
};

export const Counter = component(({ initial = 0, step = 1, onChange }: CounterProps) => {
  let count = $state(initial);
  const doubled = $derived(count * 2);

  function increment() {
    count += step;
    onChange?.(count);
  }

  return (
    <button type="button" onClick={increment}>
      {count} / {doubled}
    </button>
  );
});
```

已实现的组件规则：

- `component` 明确编译边界，参数解构得到只读的响应式输入绑定。
- 组件函数初始化执行一次；需要随状态变化的条件结构放在支持的 JSX 动态位置，普通顶层 `if` 和提前返回不会自动重新执行。
- 支持就近默认值和重命名，例如 `class: className`；不要求单独维护 defaults 对象或运行时 props schema。
- 小组件允许内联 props 类型；复杂或复用的类型再单独命名，不强制拆文件。
- 保留 `component((props: Props) => ...)`，复杂关联类型或嵌套数据可以直接访问对象。
- 泛型包装保留原始函数签名，不把 props 压成 `any`。TypeScript 的泛型、联合、Pick、Omit、NoInfer 等直接使用，不另造类型 DSL。
- 组件通过 JSX 或根挂载入口创建；直接把组件值当普通函数调用会报错。普通辅助函数继续普通调用。

默认值已按下表实现并提供行为用例：

| 情况                           | 执行语义                                       |
| ------------------------------ | ---------------------------------------------- |
| 未传入或值为 `undefined`       | 使用默认值                                     |
| `null`、`false`、`0`、空字符串 | 保留传入值；不是默认值触发条件                 |
| 默认数组或对象                 | 每个组件实例独立，不与其他实例共享             |
| 无响应式依赖的默认表达式       | 首次需要时计算并缓存，反复读取不重建           |
| 默认表达式依赖前面声明的 props | 按实际读取的依赖更新缓存 fallback              |
| 引用后面参数或形成循环         | 保持清楚的错误，不因改写而偷偷改变初始化规则   |
| 默认函数值                     | 得到该函数，不自动调用函数体                   |
| 默认值中建立订阅或发请求       | 默认值要求纯计算；副作用放在明确的生命周期入口 |

默认值使用统一的缓存 fallback：无依赖结果保持稳定，有依赖时按实际读取更新；显式输入暂时覆盖 fallback。这个规则已落地，不再是待冻结候选。

`$state(initial)` 只在创建状态时取一次初值，后续 initial prop 变化不自动重置用户状态。需要持续计算时使用 `$derived`。

### 3.2 状态、派生与副作用

```ts
let count = $state(0);
const doubled = $derived(count * 2);

const total = $derived.by(() => {
  let result = 0;
  for (const item of items) result += item.price * item.quantity;
  return result;
});

effect(() => {
  const stop = subscribeToSomething(id);
  return stop;
});
```

- 普通表达式保存执行时的结果，只有显式派生持续跟随。
- 派生绑定只读，不引入临时覆盖派生值的双重数据来源。
- 普通对象与数组按属性跟踪；类实例、DOM、Date、Map/Set 等保留原始对象，不做深代理。
- 输入对象不隐式深拷贝，通过原始别名绕过代理的修改不承诺通知；`$state.raw` 跟踪整体替换，JSON 传输使用显式数据边界。
- 普通函数传参仍传当前值；需要以后读取最新值时显式传 getter。
- 副作用跟踪同步读取，重跑前和销毁时清理。不能把任意 async 函数自动当成安全、可取消的响应式任务。

### 3.3 事件、属性与复用组件

```tsx
import type { JSX } from 'zerodep-js';

type ButtonProps = JSX.IntrinsicElements['button'] & {
  tone?: 'primary' | 'neutral';
};

const Button = component(
  ({ tone = 'primary', type = 'button', children, ...attrs }: ButtonProps) => (
    <button {...attrs} type={type} data-tone={tone}>
      {children}
    </button>
  ),
);
```

- 原生事件使用浏览器事件类型；准确提供 currentTarget，不借用 React SyntheticEvent。
- 回调 props 保持普通函数；组件业务事件按值传递，不强制创建事件总线或事件对象。
- `...attrs` 已实现为响应式排除视图，处理新增、删除和值更新。
- JSX 属性遵循从左到右的覆盖顺序。class/style 的组合由明确代码或明确能力完成，不暗中合并任意属性。
- props 绑定只读不等于深度冻结对象。深层引用、共享可写模型和父子数据所有权需要清楚约定。
- `exactOptionalPropertyTypes` 下，可选属性与显式 undefined 有区别；原生属性类型已明确允许需要的 undefined，自定义组件继续由其 props 类型表达契约。

本轮扩展使用标准 TSX 语法：`prop:scrollTop={top}` 表达客户端 property，`on:ValueChanged` 与 `oncapture:ValueChanged` 表达精确事件名。时序、类型、SSR 省略与恢复语义已同步到[原生元素](native-elements.md)和语义契约。

### 3.4 输入与状态复用

```tsx
let name = $state('');

<TextInput value={name} onValueChange={(next) => (name = next)} />;
```

受控 value 和初始化用的 defaultValue/initialValue 分开表达。是否同时支持受控、非受控以及切换模式，由具体组件契约决定；不要求所有组件套用一个通用 control 抽象。双向绑定语法在这个基础正确后再讨论。

上面的 TextInput 是应用组件示意，core 不内置 UI 控件库。原生输入的受控/非受控、同值归一化、reset、选择区、组合输入事件顺序和接管前编辑已有实现及用例；本机 Windows 真实输入基本试用已有用户反馈，范围见 forms.md。

```ts
function createCounter(initial = 0) {
  let count = $state(initial);

  return {
    get count() {
      return count;
    },
    increment() {
      count++;
    },
  };
}
```

先使用普通函数、getter 和操作方法暴露共享逻辑。普通 `return { count }` 保留取值语义，不自动改成 getter；也不为了减少几行出口代码马上增加多套宏。

### 3.5 条件、列表与 children

```tsx
<>{open ? <Panel /> : null}</>

<For each={rows} keyBy={(row) => row.id}>
  {(row, index) => <Row row={row} index={index} />}
</For>
```

For 写法已实现。同 key 替换对象和排序保留实例及编辑状态，删除时清理；内联同步回调的 row/index 是编译器识别的只读实时绑定。普通 map 和任意回调继续普通 JavaScript 传值语义。

JSX 值是可重复插入的渲染描述，每个插入位置建立独立实例和作用域；普通 children 可以转发，带参数内容使用显式调用的 render callback。JSX.Element 不能用来精确限制子组件种类。

### 3.6 根挂载与服务端入口

```ts
const dispose = mount(App, { target, props });
const disposeHydrated = hydrate(App, { target, props });
const html = renderToString(App, { props });
```

mount、hydrate 与组件 renderToString 均已实现，前两个返回清理函数。采用同步组件渲染，服务端数据在调用前准备；异步组件和流式结果根据实际需要扩展。接管行为和恢复策略见 ssr-and-hydration.md。

`renderDocument` 继续只负责模板组合；example 的 mode 切换已经驱动同一 App 的 mount 或 SSR + hydrate。

## 6. 长时间自主执行规则

用户已经授权持续执行，按以下方式推进：

5. CI 在后台运行，不空等或反复轮询；下次准备推送时检查上一轮结果并修复真实失败，最终验收必须确认目标版本通过。
6. 遇到失败先定位原因，不删除有效测试、不隐藏诊断、不退回假实现。
7. 保留用户改动，不覆盖未知工作；只清理本阶段拥有的临时文件、进程和产物，不清理共享缓存。
8. 目录整理应排除 node_modules 和构建产物，避免 Windows 移动操作遍历 pnpm 链接目标。

必须停下来讨论的情况：

- 需要推翻用户明确约束且没有满足目标的合理替代方案；日常 API 和实现调整依据证据自主决定并记录。
- 需要改变用户已明确选择的总体使用形态，且不存在兼顾正确性和维护性的合理方案。
- 需要新增外部服务、费用、凭据权限，或执行生产部署等未授权动作。完成验收后的 npm 发布已获授权。
- 出现无法判定归属的用户改动或不可安全处理的数据。
- 同一阻碍经定位仍无法推进，需要用户决策或外部条件变化。

自主执行已经开始。依据证据调整取舍并记录，不因无人值守放宽验收标准；代码保持简洁和人工可维护，适当中文注释，持续整理目录和 API 命名，Git 提交信息使用中文。
