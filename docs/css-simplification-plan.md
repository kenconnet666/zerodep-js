# 单一 CSS 组合入口与框架完善计划

日期：2026-10-11。本文保留批准的实施计划；单类组合与 API 删除已进入源码，当前验收状态以 [执行记录](framework-css-execution.md) 为准。实施依据为用户确认的单个哈希样式类、data/id 定位和继续完善当前 TSX 框架。

框架改进有独立工作包，见 [框架完善计划](framework-hardening-plan.md)。下面 P4 只负责联合验收，不代替框架实施；props、表单和类型工作先行，与 CSS 阶段交错推进。

## 1. 目标写法

```tsx
const Panel = _component(({ width, color, class: incomingClass, ...attrs }: PanelProps) => {
  const s = useCss();
  const panel = css(s.width.px(width), s.color.raw(color), incomingClass);

  return <section {...attrs} data-ui="panel" class={panel} />;
});
```

组件参数解构自动读取最新 props，不加 `_derived`。函数内直接命名 const 的 css 调用继续自动派生。传入样式结果在末尾参与组合，作者不再调用第二个合并入口。

## 2. 单个哈希类的确定含义

- 一次最终组合得到一个哈希样式类；空输入返回空结果，不登记空规则。
- 作者声明、原生 CSS 片段和本宿主已登记的 css 结果，按参数顺序展开为完整内容，再统一命名。结果不再拼接多个类名。
- 例如 `css(css('color:red;'), 'color:blue;')` 的最终内容是 `color:red;color:blue;`，不是把红、蓝两个类挂到同一元素上。
- 保留重复声明、简写/长写顺序、无效值前面的合法回退、`!important`、嵌套选择器和媒体条件；不写一个“最后一个属性胜出”的 JS 去重器。真实覆盖仍由浏览器按 CSS 层叠决定。
- “一个类”指一个组合结果，不是全应用只有一条规则。其他元素使用的基础类可以继续存在；单用途中间 css 调用优先合并到最终调用，避免多余登记。本轮不建立延迟登记或全局引用回收体系。
- 动态安全值仍通过内部 CSS 变量更新。DOM 上一个样式类不等于 css 返回值必须是裸 string；CssClass/ClassValue 可继续携带元素变量，由原生渲染展开，作者无需拆 class/style。
- 动态值变化但声明结构不变时复用类；主题 token 和不安全值仍回退实际声明，必要时更换这个单独的类。多个实例的变量互不覆盖。

### 输入识别与宿主边界

不修改属性作者返回字符串的契约，不新增 bx、CSS 片段包装器或 `{ class: ... }` 作者语法。

- 已登记的生成类按精确登记表查找其声明；嵌套 CssClass 结果同时保留动态值。
- 原生字符串片段仍按原规则拼接，不按冒号、空格或分号猜测是不是 class；数组和 false/null/undefined 仍按顺序展开或省略。
- css 不再保留任意外部类名。UI 的传入 class 组合路径以本系统产生的样式结果为契约，不承诺第三方任意类名会被展开。
- 若输入明确使用内部生成类格式，却在当前宿主没有登记，应给出可定位的错误；不把缺失规则的类名默默当作 CSS 内容。多个类名的旧结果需要重建，不保留自动兼容拼接。
- SSR 保持请求隔离，接管先恢复该请求的规则清单再组合。跨请求、跨宿主样式引用不通过全局缓存绕过隔离。
- 本轮约束 CSS 系统及 UI 的组合输出，不让 core 依赖 CSS 包。普通 DOM 的原生 class/className 属性能力不因这一重构被顺带删除。

## 3. API 删除与保留清单

| 项目                                   | 计划                            | 理由与迁移方式                                                         |
| -------------------------------------- | ------------------------------- | ---------------------------------------------------------------------- |
| `_mergeClasses`                        | 删除公开导出与浏览器/服务端包装 | 全部改为 css；不保留 deprecated 别名                                   |
| 登记器/ServerCssHost 的 `mergeClasses` | 删除重复实现与声明              | 单一路径展开声明和动态值，测试也改验 css                               |
| `className(name)`                      | 删除标记类生成 API              | 不再为识别节点额外生成 `zm-*` 类；使用 data-* 或必要的 id              |
| `CssProps`                             | 删除重复的公开类型别名          | 当前仅是 ClassStyle 的同义类型；内部直接复用既有类型                   |
| `css`、Css 属性作者与选择器方法        | 保留并统一组合                  | 作者主入口，继续标准 TSX/TS 调用                                       |
| CssClass / ClassValue / ClassStyle     | 保留必要职责                    | 传递动态变量与类型提示；不为减少名字丢掉数据或变成 any                 |
| `_buttonStyle` 等真实业务复用函数      | 保留                            | 多种按钮共用视觉规则，返回 css 结果即可；不是另一套合并 API            |
| `keyframes`                            | 保留                            | 动画声明不是普通样式类，Spinner 有实际使用                             |
| `globalCss`                            | 保留                            | 全局规则有独立的登记/更新/删除职责，不塞进元素样式类                   |
| CSS 上下文、SSR 宿主、序列化、接管     | 保留                            | 主题隔离、请求隔离和接管的必要能力                                     |
| `cssBinding` / `cssResult`             | 保留编译协议职责                | 业务不手写；允许内部简化，但不能因名称多就破坏编译输出                 |
| JSX 的 `className` 属性别名            | 本轮保留                        | 与 `className(name)` 标记函数不是一回事；避免扩大到无关 JSX 兼容性清理 |

当前已找到 13 个 UI 源文件调用 `_mergeClasses`。`className(name)` 的仓库消费主要在测试与独立消费夹具，不需要为业务节点保留标记类方案。

## 4. DOM 定位约定

- 样式哈希是实现结果，不作为稳定选择器、测试身份或业务 ID。
- 必要的组件/部件定位使用 data 属性，例如 `data-ui="panel"`、`data-part="label"`；不机械地给每个 DOM 节点加标签。
- label/for、aria 关联等需要唯一身份时继续使用 id 和已有 `_id()`，保持 SSR/接管一致；不使用全局递增计数或临时随机值代替现有协议。
- 现有 getByRole/getByLabel 等语义化测试保留。将依赖样式哈希定位节点的用法迁到 data/id，不把测试全部改成任意属性查询。
- ButtonGroup 等已有 CSS 结构协作继续按原生选择器工作，不因去掉标记类新增 Provider 样式覆盖层。

## 5. 分阶段实施

### P0：恢复基线并固定新契约

先检查 a269fda 的 CI。已定位失败为 select 绑定说明更新后，原生 DOM 生成声明未同步，native:check 报“声明已过期”；同步生成器产物并执行焦点一致性检查。其他阶段不在这个未恢复的基线上直接扩大改动。

以本文件约定覆盖旧 `_mergeClasses`/外部类名组合方向。当前代码仍保留旧 API，不能把规划写成已完成能力。先补组合测试，再修改实现。

### P1：只改 CSS 组合内核，先验证再迁移 UI

范围：packages/css 的规则登记、绑定结果组合、类型及相关测试。

- 将 css 的字符串类引用和动态结果归入同一条展开路径；顺序合并最终声明与元素变量。
- 结果仅为一个已登记哈希类或空结果；不保留外部类名集合与空类登记。
- 固定跨宿主、旧多类结果、缺失哈希规则的诊断行为；保留原生 CSS 片段能力，不另造声明解析器。
- 不做属性排序、裁剪、CSS 层叠模拟、LRU 或规则引用计数。复用完整内容去重。
- 如果必须改变编译协议，先记录 ABI 变化并同步 core/compiler；普通实现修复或删除作者辅助 API 不机械升级 ABI。

通过门槛：静态/动态结果可以重复组合；空项、顺序、嵌套规则、不同实例、SSR 清单恢复都有焦点测试。

### P2：试点 ButtonBase 与 Icon

把 `const style = css(...); class={_mergeClasses(style, incoming)}` 收敛为 `const style = css(..., incoming); class={style}`。只有真正共享的样式函数保留独立结果。

验证调用方样式、默认主题、字号、disabled/focus、slot 转发、用户 style 覆盖、动态 props 和实例保留。CSR/SSR 都正确后再批量迁移其他组件。

### P3：迁移消费并删除旧入口

迁移其余按钮、Text/Ripple/Spinner、ButtonGroup、Flex/Grid、Provider，以及 compiler/core/CSS 测试、示例、文档和独立包消费。

- 删除 `_mergeClasses`、登记器 mergeClasses、className 标记函数与 CssProps 重复公开别名；清理导入、声明和无效文档，不保留兼容转发。
- CSS 独立消费的 css-tree 夹具改验真实作者/声明的按需导入，保留 tree-shaking 与无宿主可用的作者能力检查，不能通过删断言规避验收。
- 更新当前指南与 API 清单；有价值的历史研究保留并标明被新计划取代。
- 预编译 UI/应用统一重建，防止旧产物仍导入已删入口。清理本任务产物与空目录，不删除用户 IDE 配置、运行数据或共享缓存。

阶段之间可以临时保留旧实现帮助迁移，但最终交付不保留旧 API，不单独发布中间兼容状态。

### P4：与框架完善合并验收

本阶段接入框架主线 F1–F7 的成果；框架不是到 P4 才开始。首个独立包 F2/F3/F6 应在 CSS 大规模迁移前交付。

选一个“多层表单组件 + 根对象替换 + 状态样式”的业务场景，把上一轮审查落到组合行为：

- props 参数直接解构/default/rest，传入 class 变化也直接参与 css；不增加 `_derived` 包裹 props 的要求。
- 原生及自定义组件 bind、回调转发、可选值、输入清空、reset、接管前输入与整体替换保持一致。
- 列表同 key 换数据、排序后 index、行草稿与焦点保留；For 继续用现有参数、行组件或派生解构。
- 最新回调、分支清理、卸载取消与过期异步结果保护继续验收；不新增 task/query 或跨 await 跟踪。
- CSS 普通值变量化/特殊值 class 回退、主题切换、显式 style、多个实例与 SSR 不串值。
- 完整 TS7 写回诊断、真实 hover/补全和预编译消费一起检查；普通快照合法，不加入粗糙的“所有取值都警告”。

## 6. 核心验收清单

| 领域     | 必须成立                                                                       |
| -------- | ------------------------------------------------------------------------------ |
| 单类输出 | 单个组合结果只有一个哈希样式类；空结果不登记空规则                             |
| 原生层叠 | 参数顺序进入 CSS；重复/无效声明回退、简写、important、嵌套条件不被 JS 去重破坏 |
| 组合传递 | 已登记静态类、动态 CssClass、条件和数组经过多层组件后仍可组合                  |
| 响应式   | props/主题/动态变量变化正确；普通变量和辅助函数参数仍按既有边界取值            |
| 变量清理 | 特殊值或省略切换后无旧变量残留；同一共享样式函数的多个实例互不污染             |
| SSR      | 每请求隔离、确定内容命名、清单安全序列化、先恢复再接管；无新全局样式缓存       |
| 类型/API | 无 any 放宽；删除的根导出确实不存在，编译协议仍可被预编译产物正确消费          |
| DOM 身份 | 测试/行为不依赖样式哈希；必要 data/id 与可访问性关联稳定                       |

## 7. 外部参考与明确不做的事

Svelte 仍是状态、props 和生命周期边界的主要参考；Solid/Vue JSX Vapor 用来检查 TSX、列表和类型工具的处理。Rezact 的简短写法作为比较，不采用其按 `$` 名称改变普通参数含义、静态扫描全部依赖或 DOM 轮询清理的方式。

本轮不增加响应式父类、全变量引用、splitProps/mergeProps、Index/Show、新样式 DSL、手写 bx、普通函数自动升级、自动异步呈现、通用 CSS 外部适配器或缓存回收体系。优化的结果应是更少的作者入口和更可靠的既有行为。
