# 持久化任务管理试点

试点位于现有 example 的 `/tasks`，使用独立 HTML 与客户端入口，与框架验证页共享开发/预览服务器。它消费 core、SSR 和 Vite 包，不创建没有实际职责的新包。

当前已完成本地业务验证，完整浏览器矩阵交给 CI；已交付证据以 execution.md 和生产计划为准。框架验证页还可以打开/关闭同一个任务组件，用于验证异步组件的生命周期。

## 启动与数据

运行 `pnpm dev` 后打开 `http://127.0.0.1:5173/tasks`。构建预览使用 `pnpm build`、`pnpm preview`，地址为 `http://127.0.0.1:4173/tasks`。页面链接在 SSR/CSR 间切换并保留搜索与状态筛选，也可直接使用 `?render=csr` 或 `?render=ssr`。

日常数据文件为 `apps/example/.data/tasks.sqlite`。服务启动时不会自动清空或反复插入示例数据；记录提交后重新打开数据库仍保留。需要独立验证时可运行 `pnpm --filter @zerodep-js/example preview --tasks-file :memory:`，或明确指定另一个数据库文件。已有其他用途的数据库会被拒绝接管。

## 行为约定

业务包含新增、编辑、完成、删除、搜索和状态筛选。SQLite 文件保存数据，更新/删除携带 revision，过期写入返回冲突；界面保留草稿并显示错误，允许刷新后重试。Node 24 的 SQLite 只属于此示例服务器，用户数据默认存放于 example 的 `.data`，不进入 Git。测试使用内存或明确创建的临时数据库，不清理日常数据文件。

保存期间仍可继续输入，较早响应只确认对应的提交，不覆盖之后的草稿。冲突时更新服务器信息但暂不重查整张列表，避免新标题不再匹配搜索而让编辑行消失；“恢复服务器内容”与再次保存由用户选择。主动刷新或切换筛选会重新应用查询，已移出视图的行随组件生命周期销毁。

初始查询在服务器完成，选定数据通过安全 JSON 入口传输，CSR 与 SSR 使用相同初值。客户端的搜索请求取消旧任务，过期响应不覆盖新结果；卸载取消未完成请求。业务先用普通状态、回调、effect 和 AbortController 表达，根据实际缺口再判断是否需要框架 API，不提前引入通用数据层。

取消请求用于释放浏览器侧等待和忽略过期结果，不会回滚服务端已经提交的写入；重新打开页面会查询已保存的数据。

## 验收

- 实际增删改查、数据库重新打开后数据仍在、参数校验与过期 revision 冲突。
- SSR 无脚本可阅读，hydration 复用节点；同样业务可用 CSR 启动。
- 同 key 记录刷新、重排后保留输入草稿、焦点与选择；保存响应不清掉用户之后输入的新草稿。
- 旧搜索比新搜索晚到、请求失败/重试、操作冲突和页面卸载时的请求清理。
- 实际开发更新、工作区包产物消费、浏览器完整矩阵与使用说明。

本地完成 4 项数据库/校验用例、10 项 Chromium 业务用例，并检查桌面与 390 像素手机布局，没有横向溢出。真实开发入口通过组件更新、局部状态重置、SSR 模块更新和源文件恢复验证；保留同一 document，未整页刷新。原验证页的 5 项 Chromium 冒烟也通过。三浏览器结果仍以本阶段 CI 为准。

试点已推动两项框架修正：派生布尔值不应被误当成输入的 TypeScript 条件别名；noscript 在脚本启用时具有特殊解析方式，不能按普通 DOM 子树接管。两者均在编译器/运行时修复并增加对应回归，未用业务写法绕过。

它是本机试点，服务器绑定 127.0.0.1；写请求校验来源与 JSON 数据。多人身份体系和外网部署不属于这个示例的承诺。试点暴露的框架问题必须回到相应运行时/编译器修复并留下回归证据，不能通过业务代码隐藏。
