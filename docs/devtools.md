# 开发检查与热更新

开发编译保留 HMR 和状态恢复，默认不安装面板。需要界面时由应用显式开启；主示例已经开启：

```ts
if (import.meta.env.DEV) {
  void import('zerodep-js/devtools').then(({ _inspect }) => _inspect());
}
```

生产构建不执行该入口，独立产物验证仍拒绝开发模块进入生产包。

## 能看到什么

- 当前挂载的组件及父子关系，包括名称、实例编号、原始文件和行号。
- 组件函数直接声明的 _state 数据。值作为有限长度的只读预览显示，访问器不求值，外部实例显示标记。
- 最近最多 200 条挂载、卸载、HMR 和异常事件。打开面板时每 500 毫秒采样状态变化；关闭时停止采样。它不统计每次依赖触发，也不是性能分析器。
- “重新初始化此组件”会重建该组件及其子树，回到当前源码的初值，同时清理旧资源。

登记范围是经当前开发编译器处理的模块顶层组件，包含匿名默认导出。组件内部辅助函数中的状态、模块状态和预编译依赖内部状态不登记为组件本地状态。普通 props 可能有 getter，也不自动展开执行；需要时直接在源码处调试。

供自动化检查的只读快照位于开发页面的 `window.__ZERODEP_DEVTOOLS__.snapshot()`。`reset(id)` 可手动重置实例，`clearEvents()` 清空事件。该桥和 `zerodep-js/devtools` 都属于开发协议，不是应用应依赖的生产数据接口。事件仅保留编号和有限长度文字；卸载时移除活跃实例与作用域引用，面板不保存历史对象图。

## 热更新会保留哪些数据

```tsx
export const Profile = _component(() => {
  let count = _state(0);
  const form = _state({ name: '' });
  return (
    <>
      <h1>修改这里的文案</h1>
      <input bind:value={form.name} />
      <button
        onClick={() => {
          count++;
        }}
      >
        {count}
      </button>
    </>
  );
});
```

把 count 点到 2、在输入框写入姓名，然后修改 h1 文案：在兼容的组件模块更新中，count 和 form 会恢复到刚才的数据。改成 `_state(10)`，改状态名称或类型，或修改 props 的声明/默认值，会重新初始化；排版和注释不引发这种重置。检查面板记录本次尝试保留的数量或重置原因。

这里保留的是数据，组件初始化和子树仍重新执行。旧的 effect、事件、ref 与取消信号按原生命周期释放，新副作用在新 DOM 提交后运行。先准备新子树，成功后替换旧子树；新初始化/渲染失败会回收尝试创建的资源，已有可运行页面保留，修复源码后可恢复更新。

为了避免把外部对象错误复制成组件私有数据，迁移范围有明确限制：

- 原始值，以及直接由字面量创建的普通对象/数组可迁移；内部共享引用、循环和稀疏数组保留。
- 函数、DOM、AbortController、类实例、访问器、Map/Set 等按初始化逻辑重新建立。复制有节点/深度上限，超过上限也重置。
- 初始化为 props、工厂函数或外部引用的对象不自动复制。辅助函数里的 _state、history/router 等有生命周期的句柄不迁移。迁移会产生新的对象身份，只保留本次迁移数据内部的共享引用，不保证与外部引用仍指向同一对象。
- 更新一个模块时重建其中的组件实例；重建父组件也会重建其子实例。**不承诺保留整个组件树、DOM 节点身份、焦点、选择区或未登记的闭包数据。** 精确的业务保存应使用显式状态归属和持久化，不能依赖 HMR。
- 只有组件导出的模块能够在组件层接收更新。增加普通运行时导出、改组件身份或导出结构时交给导入方重建；最后一个本地组件被移除时整页刷新，避免静默保留旧页面。

这些限制优先保证新代码生效和旧资源释放，不尝试猜测任意闭包如何迁移。若需要更强的组件树保留，应另外设计可验证的实例身份协议，不能在本机制上用数组位置硬凑。

## SSR、错误和生产隔离

开发 SSR 使用与客户端一致的开发模板结构，但不登记请求实例、不保存请求数据、不接收客户端组件 HMR；Vite SSR Module Runner 按正常依赖失效重新导入。首次 hydration 仍验证并复用服务端节点。

编译错误由 Vite 覆盖层报告原始 TSX 位置。组件初始化异常和浏览器未处理异常进入检查面板；已有 ErrorBoundary 继续负责其支持范围，不把调试面板当成异常处理器。面板不吞掉应用异常，也不捕获所有第三方回调错误。

`pnpm test:dev` 覆盖状态保留/重置、监听释放、编译/执行失败恢复、混合导出、转发入口、面板和开发 SSR 接管。生产独立消费额外检查输出模块，确保客户端、服务端及小入口均未包含 devtools 实现。页面离开时关闭面板计时器和监听；测试浏览器、开发服务器和临时目录通过 finally 清理。

## 参考与取舍

参考 [Vue Devtools 功能](https://devtools.vuejs.org/getting-started/features)、[插件接口](https://devtools.vuejs.org/plugins/api)和[实例注册表实现](https://github.com/vuejs/devtools/blob/396e108b1c4e5d8ce5abca8c54f3bcab03413adb/packages/kit/src/runtime/registry.ts)的组件身份、父子关系、有限事件和实例移除职责。这里没有伪造 Vue app，也不引入 Vue 运行时或其整套插件协议。

Vite 的 accept、invalidate、prune 依据[官方 HMR API](https://vite.dev/guide/api-hmr)。实测修正了两个边界：SSR 不应接收客户端组件更新；模块变为混合导出时，必须保持可失效的接收入口，再把更新交给导入方处理。
