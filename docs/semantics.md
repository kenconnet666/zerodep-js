# 执行中的语义契约

2026-10-01：用户授权目标模式，要求完整生产可用、适当取舍、人工可维护，并允许有依据地调整实现与测试。本文记录执行选定的契约；调整时记录原因与迁移影响，不把旧候选文档当成永远不变的限制。

## 状态与计算

- `$state` 显式声明变量式状态，普通读写由编译器转换；普通变量、函数传参、对象字面量和 return 保持取值语义。
- 普通对象/数组按属性跟踪；不代理类、DOM、Date、Map/Set。原始对象不隐式深拷贝，经原始别名绕过代理的操作不承诺通知。
- `$state.raw` 是显式浅状态入口，只跟踪整体替换。它不要求使用 `.value`。
- `$derived` 与 `$derived.by` 为纯计算，按需执行、动态跟踪同步读取；禁止计算期间写状态或建立副作用。
- 相等性基线为 `Object.is`。派生失效不等于值已变化，结果相等时跳过下游 effect。
- 写入立即可读，派生立即读取也必须一致。中间连续写入允许合并 DOM 和 effect 更新。
- `untrack` 仅取消读取的依赖登记，不豁免纯派生的写入限制。

## 生命周期与调度

- 组件初始化一次；动态 JSX 区域跟踪后续更新。普通顶层条件与提前返回不自动变为响应式结构。
- `effect` 必须属于组件、分支、列表行或显式 `createRoot`。禁止无作用域创建不可回收的订阅。
- effect 首次和后续执行在微任务批次内，DOM 更新先于用户 effect；同步创建/更新过程中不运行半初始化的用户副作用。
- 重跑先销毁上一轮的子作用域，再按注册的逆序执行清理；卸载同样清理，重复 dispose 无副作用。
- `onCleanup` 归属当前作用域；effect 返回的函数属于该轮清理。清理不收集依赖。
- `batch` 合并通知；`flushSync` 用于需要立即观察 DOM 的明确边界，禁止在计算或正在执行的 effect 中重入刷新；`tick` 等待本轮刷新。
- 不跨 await 隐式保留跟踪或作用域。异步请求由取消、清理与过期结果判定负责。
- 一处异常不阻止其他独立作用域清理或独立任务更新；错误继续传播，不能吞掉。后续错误边界沿组件所有权实现。

## 组件与 props

- `component` 为显式组件边界，保留原函数泛型签名；普通函数仍按普通函数调用。
- 顶层参数解构、别名、默认值与 rest 是正式支持目标。复杂嵌套解构先提供明确诊断和 `props.user.name` 等替代写法，不静默失去响应性。
- 输入绑定只读；深层对象不递归冻结。业务写入优先通过回调交回拥有者。
- 默认值仅在输入为 undefined 时使用。每个实例独立缓存，无依赖默认值稳定，有依赖 fallback 按依赖更新；显式值暂时覆盖 fallback。
- 默认表达式引用前面参数时读取其当前值，不放宽前向引用规则。默认值是纯计算，不能放订阅或发请求。
- `$state(initial)` 只取创建时初值，后续 prop 变化不重置状态；回调 prop 在事件发生时读取最新函数。
- rest 是排除已解构键的实时视图，支持新增、删除、覆盖次序；不是初始化时复制的普通对象。
- TS 原生检查与框架诊断共同构成语义门槛。跨回调沿用实时绑定的外层收窄不受支持，需在本次调用重新读取判空或显式保存快照；无法可靠转换的形式应报错。

## 内容、列表与根入口

- JSX 使用框架自己的元素、事件和 children 类型；原生事件不包装成 React 事件。
- 普通 children 支持转发。重复创建内容使用 render 函数；节点插入、所有权和实例化协议在 DOM 实现时用用例冻结。
- `For` 使用稳定 key；内联回调的 row/index 是编译器识别的实时绑定。同 key 替换数据读取新对象、保留行实例；删除销毁，重复 key 报错。
- 普通 map 保持普通计算，不默认为有身份保留的列表机制。
- `mount(App, { target, props })`、`hydrate(App, { target, props })` 返回 disposer；SSR 从同步 `renderToString(App, { props })` 建立正确基线。
- 完整生产目标包括受控表单、IME/选区、错误恢复、context、ref、属性转发、声明消费、HMR、SSR/hydration 与安全边界；不以只支持计数器代替完成。
- SSR/CSR 由应用入口选择，切换模式允许重新导航；不承诺把已挂载实例无刷新迁移到服务端。
- SSR 每请求独立 scope，用户 effect 不在服务端执行；不自动序列化全部 props，客户端初始数据需要明确的传输边界。

## 交付与合理取舍

目标是有清楚支持范围的完整生产框架，而不是对所有可能特性的承诺。内置路由、全栈数据层、RSC、流式 SSR、动画与 UI 组件库不自动进入核心职责；真实使用证明缺失能力影响生产时，应调整计划并补齐。

浏览器运行时优先无第三方运行时依赖，编译与开发工具允许依赖。命名、目录、私有 helper 可以随真实职责重整；不为兼容尚未发布的实验内部接口保留重复抽象。
