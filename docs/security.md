# 安全边界与发布审查

框架负责把声明的 UI 和选定的数据放入对应上下文，不是 HTML/URL/JavaScript 净化器。应用代码与组件定义属于可信代码；外部数据应经过应用自己的校验。本页说明保证的位置，避免将转义或类型检查误当成对所有输入的安全证明。

## 输出与信任边界

| 入口                                         | 框架处理                                                   | 应用责任                                                         |
| -------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 普通 JSX 文本与属性                          | SSR 分上下文转义，客户端使用 DOM API；替换传输不完整的字符 | 选择可公开的字段，校验业务含义                                   |
| 原始文本元素                                 | 不插入结构注释；结束标签、脚本双重转义和不闭合注释明确报错 | script/style 内容必须可信；JSON 用 serializeData                 |
| serializeData                                | 编码 JSON 并转义 HTML 敏感字符，避免提前关闭 script        | 显式选取数据，不传输密钥；恢复时按业务 schema 校验               |
| href、src、srcdoc、CSS URL 与客户端 property | 保持浏览器原生语义及值类型，不执行通用内容净化             | 根据场景限制协议、来源和嵌入内容；需要时使用合适的 sanitizer/CSP |
| renderDocument                               | 校验占位符数量，按指定模式组合文档                         | template 和 render 返回值必须来自可信模板/渲染器                 |
| DOM ref 与自定义元素                         | 明确所有权、注册顺序、属性恢复及清理                       | 对第三方库、事件 detail、命令式 DOM 操作及外部资源负责           |

SSR 不自动序列化组件 props、服务端异常或资源。ErrorBoundary 只输出应用选择的 fallback，错误对象不进入接管协议。浏览器端仍须使用与服务端一致的初始数据、构建产物和合法 HTML 嵌套；严格 hydration 报告不一致，显式 replace 才会重建。

请求状态在 renderToString 的作用域内创建并在成功或失败时释放。模块级可变对象仍按 JavaScript 规则共享，因此不能将请求凭据或用户状态存入共享模块后期待框架隔离。

## 审查及回归证据

- 普通文本/属性注入、JSON 的结束标签与特殊字符、请求隔离和错误清理：packages/ssr/test 下的用例及独立包消费验证。
- 原始文本内容、非法名称、HTML/SVG 名称规范化：packages/core/test/native.test.ts 和 packages/ssr/test/raw-text.test.ts。
- 实际 HTML 解析、后续节点不被 script 吞掉、JSON 内容不生成额外节点、CSR/SSR 文本更新与接管：tests/e2e/serialization.spec.ts、hydration.spec.ts、attributes.spec.ts；完整三浏览器矩阵由 CI 运行。
- 生命周期、失败清理、缓存回收与多轮次请求/根替换：scripts/verify-stability.mjs 和浏览器稳定性用例；指标记录见 stability.md。
- 示例服务的参数化 SQL、输入校验、写入冲突、来源与 Host、请求大小：apps/example/test 与任务业务浏览器用例。这是本机消费示例，不提供互联网部署所需的鉴权体系。
- 发布工具固定官方 registry、提交和 tgz 完整性；token 只在环境传递，临时 npm 配置仅保存变量引用；禁止异质版本覆盖和未验证的稳定 tag 提升。

2026-10-01 的最终边界审查实际复现并修复了 iframe 字符引用/动态注释、script 双重转义、plaintext 无法闭合和非 ASCII 首字母标签无法解析等问题。针对性单元与 Chromium 验证通过后，再由候选提交的完整 CI 确认其发布状态。这些证据不承诺所有应用代码、浏览器扩展或任意无效 HTML 都安全。

候选发布还需记录生产依赖审计、凭据扫描、Git 提交、完整 CI 和注册表消费结果。以对应版本的发布记录为准，扫描通过不等于未来没有漏洞；新缺陷必须保留复现用例并按升级/回滚流程处理。
