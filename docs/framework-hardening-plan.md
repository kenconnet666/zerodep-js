# 框架语义与 TSX 易用性完善计划

日期：2026-10-11。状态：规划，尚未实施下列新工作包。本文是独立的框架主线，不是 CSS 重构结束后的附带测试清单；与 [CSS 简化计划](css-simplification-plan.md) 交错推进。

## 1. 保持的方向

- 以 Svelte 的状态、派生、props 与生命周期边界为主要参考，继续使用标准 TSX。Solid/Vue JSX Vapor 用于对照细粒度更新、列表和类型工具。
- `_state` / `_derived` 显式声明，后续变量直接读写；不引入 .value、响应式父类、全变量引用或按变量名称改变普通参数含义。
- `_component` 顶层参数解构、别名、默认值和 rest 自动保持最新输入，不需要 `_derived`、额外 props 宏或 bind 字段名单。
- 普通参数、局部解构、返回值遵循 JS 取值；共享对象字段修改与根引用替换分开理解。快照是合法业务需求，不一律警告。
- 组件 setup 执行一次，动态 JSX 持续更新；不改为组件整体重跑。
- 新能力必须能解决具体重复业务问题。已有能力先复用，不为对应外部框架的 API 名称新增入口。

## 2. 当前证据与本次计划的区别

已有工作包括：派生解构、props 根对象替换与 CSS/事件组合、嵌套宏转换修复、props 只读写入诊断补齐、select multiple 写回类型修复。这些不重复算作下一阶段的新功能。

下一阶段的交付应包含：有明确覆盖范围的语义矩阵、经复现的缺陷修复、准确的源码诊断、可复用的实际 TSX 示例及对应验收。不能为了凑工作项改写已经正确的运行时，也不能只写“全面检查”而不给场景和结束条件。

## 3. 独立工作包

### F1 / P0：变量、派生和编译转换的正确性

用户问题：看起来是普通 TS，实际行为却可能因转换改变，尤其在嵌套函数和表达式组合中。

实施范围：compiler 的 compile/derived/guards，与 core 的 state/reactivity。先将已有用例对应到语义矩阵，仅对未覆盖组合补例；复现差异后才修转换或运行时。

具体工作：

1. 核对赋值表达式返回值、前后自增、逻辑/复合赋值、BigInt、短路和接收者/参数求值次序，不能只看最终状态。
2. 检查派生中的普通辅助函数、嵌套调用、条件切换、异常后恢复；依赖由实际同步读取收集，不改成只扫描调用点。
3. 核对派生解构的默认值、rest、计算键、数组项和共享求值次数，以及纯计算期间写状态的拒绝。
4. 宏导入别名、作用域遮蔽、嵌套声明和源码映射使用同一组正反例。诊断不得指向生成临时变量。

完成标准：每项要么有既有通过证据，要么有先失败后修复的回归；普通函数传参和有意快照不被自动升级为引用。输出一份短矩阵，不新增状态 API。

### F2 / P0：props、组件组合和 children

用户问题：组件参数解构应该自然可用；包装多层后，输入、回调和属性转发不能停在初值。

实施范围：components、runtime props/component、检查投影及组件类型。

具体工作：

1. 覆盖标量、对象、别名、默认值、rest 的两层/三层转发；包括属性新增、删除、显式 undefined、父级对象整体替换。
2. 用实际泛型字段组件检查 props 推断、可选回调、class/style 与原生属性转发，不用 any 掩盖推断失败。
3. 检查事件中最新回调与最新 props 读取、局部状态不重置、默认对象实例隔离。
4. 检查普通 children 与参数化 render 回调的类型和清理；复用函数不被误当作自动执行的 children。
5. 明确顶层输入只读与深层共享可写对象的区别。对确定非法的写入提前诊断；复杂嵌套 props 解构继续给出对象字段访问替代，不悄悄变快照。

完成标准：一个泛型字段组件在多层包装、父输入替换和 callback 更新后行为与类型一致；props 参数不增加 `_derived`；CSR/SSR 都能呈现，子实例和局部状态保留。

### F3 / P1：表单绑定完整性与写回类型

用户问题：输入组件包装后模型类型、默认值和用户编辑容易不一致；不能通过少写 bind 换来隐式规则。

实施范围：native bindings、DOM input/attributes、SSR 表单输出、typed-projection，以及应用示例。

具体工作：

1. 基于现有 value/onValueChange 协议制作可选值与泛型模型的包装夹具，覆盖两层转发，不增加另一套双向绑定 API。
2. 检查 checked/group/valueAsNumber/select 的实际写回类型、空值、多个 binding、显式属性与 spread 冲突、只读目标和诊断位置。
3. 检查 bind 与用户事件共存：绑定先写回，用户回调读取更新值；添加回调不得关闭自动写回。
4. 覆盖 IME、同值归一化、原生 reset、父级模型替换、接管前编辑；保留已有用例，仅补跨组件的实际缺口。
5. 给数字归一化、稳定 ID 选择器和普通请求表单提供简短业务写法；不能为了统一类型强行把原生 option 值扩展成对象。

完成标准：原生控件与包装控件在相同操作下得到相同模型；类型可检测错误写回；无损保留选区和接管前输入。select 上一阶段的修复作为基线，不重复报成功。

### F4 / P1：条件、列表身份和数据替换

用户问题：后台列表刷新返回新对象，不能因此丢草稿/焦点；隐藏分支不应继续持有业务资源。

实施范围：render/loops、runtime flow、DOM 列表/分支挂载与 SSR。

具体工作：

1. 用“同 key 换对象 → 排序 → 过滤 → 删除 → 恢复”的连续场景检查 row/index、事件、节点身份、输入草稿和清理次数。
2. 检查空值、空列表、重复 key 错误及恢复；子组件 props 解构与行数据更新一起验证。
3. 检查条件选择未变时不重建同一分支，条件失效时先清理子绑定，避免子表达式访问已失效的数据。
4. 完善初始化 if 与动态返回/JSX 条件的诊断说明、示例和源码定位；不将普通 if 改成隐式响应式控制流。
5. For 继续使用明确 keyBy；多字段读取用现有派生解构，复杂行提取组件。参数解构扩展单列候选，不作为本阶段默认改动。

完成标准：连续业务操作中节点与草稿身份正确，旧对象不再接收当前行事件，资源只清理一次。保持现有 For，不增加 Index/Show 或自动把 map 升级为有状态列表。

### F5 / P1：生命周期、错误恢复与普通异步请求

用户问题：组件切换、快速搜索和卸载时，旧请求、旧订阅或失败清理可能继续影响当前页面。

实施范围：reactivity/lifecycle、作用域、ErrorBoundary、ref/Portal/lazy 的资源协作，及 requests 示例。

具体工作：

1. 检查 effect 重跑、显式停止、根销毁、清理中重入和抛错时的取消与释放顺序，不能依赖 DOM 轮询判断资源归属。
2. 用“搜索 A → 搜索 B → A 晚返回”和卸载后返回的例子，验证 AbortSignal 与写回前检查；补足错误、loading 和重试的应用代码。
3. 检查 ref 替换、Portal 迁移、lazy 完成与分支销毁交错时，资源不会重复创建或遗漏回收。
4. 明确 ErrorBoundary 能接住的同步/effect 错误与普通 Promise 拒绝的区别，错误回退自身失败交给外层。
5. 请求模式提炼在应用示例/文档中，不恢复 task/query 包，不新增通用异步状态对象，也不跨 await 隐式保留跟踪。

完成标准：旧结果不会覆盖新数据；成功、失败、取消和卸载路径都有明确责任；异常清理不阻止其他资源释放。

### F6 / P1：TSX 类型、诊断与编辑器一致性

用户问题：编译可以运行不等于 TS 类型正确，IDE 没报错也不等于写回安全；错误必须能找到作者源码位置。

实施范围：官方 TS7 检查投影、语言服务协议、JSX 声明与生成脚本，不修改 SDK 内核。

具体工作：

1. 将 F1–F5 的代表性正确/错误片段同时用于 compile、项目 checker 与新启动语言服务的焦点验证，避免两套边界漂移。
2. 验证泛型/可选 props、事件 currentTarget、children、bind 写回及 class 类型；保留真实声明来源的 hover、补全和导航。
3. 对确定错误补充中文修复方向，检查改动落在原始绑定或表达式上；不对合法快照强加警告，不自动改写语义含糊的代码。
4. 修改 native/jsx.ts 或生成数据源时，同步 native/elements.ts 等产物并执行对应 check；上一阶段遗漏生成注释的问题进入交付清单。
5. 文档分别说明原生 TS、框架增强、新启动服务和当前 IDE/MCP 缓存状态。需要重载时先给出独立验证证据，不靠重启碰运气。

完成标准：所选片段在 CLI 与独立 LSP 的类型/框架诊断一致；错误位置准确、补全可应用、生成检查通过。本地仅跑焦点协议/类型用例，完整语言检查交 CI。

### F7 / P2：SSR、接管与开发状态的收尾验收

用户问题：浏览器单独运行正确，不代表首屏服务端输出、接管和开发更新正确。

实施范围：SSR、hydrate、序列化、_id、context、dev/HMR 与预编译消费。

具体工作：

1. F2–F5 的核心夹具同时走 CSR/SSR，核对节点复用、接管前输入、稳定 ID 和事件接线。
2. 核对并发请求的状态/context/CSS 隔离，服务端不执行用户 effect；不把模块单例误当请求状态。
3. 验证错误接管的恢复清理、Portal/lazy 占位与恢复后的最新 props。
4. 检查 HMR 对可迁移局部状态的保留和不兼容结构的重建，不承诺迁移任意闭包或外部资源。
5. 独立 tgz 消费验证编译协议、声明、按需打包及 CSS API 删除后的预编译库重建。

完成标准：同一提交完整 CI 通过后，才记录本阶段验收。源码交付与 npm 发布分开，不新增流式 SSR 或异步呈现协议。

## 4. 首个实际工作包

先做 F2 + F3 + 对应 F6，产出一个两层包装的泛型字段组件与可替换表单：

```tsx
const NameField = _component(({ value, onValueChange, ...attrs }: NameFieldProps) => (
  <input {...attrs} value={value} onInput={(event) => onValueChange(event.currentTarget.value)} />
));

// 父组件直接绑定模型字段；替换 form 后继续写入新对象。
<NameField bind:value={form.name} />;
```

工作包括真实编译/类型/浏览器行为、两层转发的修复或覆盖补足，以及说明默认值、空值、回调顺序的简短文档。不是只添加一个静态示例；如果既有实现已正确，就保留并记录证据，不重写运行时。CSS 简化随后接入同一夹具作为样式链路，不阻塞框架主线先交付。

## 6. 仍需单独讨论的能力

For 参数解构、props 深层参数解构、可覆写 derived、组件参数直接写回、退场动画、响应式 Map/Set、自动异步呈现均不借这次完善直接加入。遇到真实重复场景时给出当前写法、候选写法、类型/SSR/清理成本，再决定是否实施。
